# Local Prompt Injection Lab — Kali Linux / Ubuntu

This standalone lab accompanies [Chapter 7: Prompt Injection in LLMs](../../07-prompt-injection-in-llms.md). It needs no hosted account, private environment, or paid LLM API.

## What You Will Test

- Direct attempts to override a chatbot's application instructions.
- Indirect injection through a fictional email and retrieved document.
- A simulated workflow-action marker that **does not execute anything**.
- Whether the model reveals an **exact fictional marker** supplied in context.
- Why removing sensitive context is stronger than attempting prompt-only secrecy.
- Markdown inline and reference-style image inspection, with **no URL fetching**.

## Safety Boundaries

This is an intentionally vulnerable educational app. Use only fictional data. Keep it on `127.0.0.1` or an isolated local network. It does **not** connect to real email accounts, ticket systems, external servers, databases, or cloud APIs.

## 1. Requirements

- Kali Linux or Ubuntu.
- Python 3.10+ (current version recommended).
- A local Ollama installation (https://docs.ollama.com/linux).
- A small downloaded model such as `llama3.2:1b`.
- A browser and a few gigabytes of available RAM; inference speed varies by CPU/GPU.

Install basic dependencies:

```bash
sudo apt update
sudo apt install -y python3 python3-venv python3-pip curl jq
```

Install Ollama using the official Linux instructions (do not install obsolete vulnerable versions just to reproduce a historical CVE):

https://docs.ollama.com/linux

Verify:

```bash
ollama --version
curl -s http://127.0.0.1:11434/api/version | jq .
```

Start Ollama if it is not already running as a system service:

```bash
ollama serve
```

In another terminal:

```bash
ollama pull llama3.2:1b
ollama list
```

## 2. Install the Lab

From the root of your GitHub repository:

```bash
cd labs/prompt-injection-lab
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt
```

## 3. Start the App

```bash
export OLLAMA_MODEL=llama3.2:1b
python -m streamlit run app.py \
  --server.address 127.0.0.1 \
  --server.port 8501
```

Open **http://127.0.0.1:8501** in your browser.

If your Ollama API is on a different **trusted** host, configure `OLLAMA_URL` (full `/api/chat` endpoint). Do not publish the insecure lab to the internet.

## 4. Exercise Guide

| Exercise in chapter | Select in the app | Goal |
|---|---|---|
| 7.12 | Direct user instruction | Test a user-level authority claim |
| 7.13 | Indirect: untrusted email | Test whether email content redirects a summary |
| 7.14 | Indirect: retrieved document | Test the RAG instruction/data boundary |
| 7.15 | Markdown rendering inspection | Spot reference-style links before rendering |
| 7.16 | Terminal | Inspect the local Ollama API safely |

### Testing Tips

1. Record the authorized task first.
2. Try one injected payload and record the full response.
3. Compare vulnerable and hardened modes.
4. Repeat a few times: LLM outputs vary even at low temperature.
5. A canary finding requires an **exact match** to the synthetic marker in the response.
6. The simulated `[ACTION: CLOSE_TICKET]` string is **never acted upon**.

**Important:** The hardened mode excludes the test marker from model context; it is not a guarantee that every possible injection fails. The exercise is about architecture and evidence, not an all-purpose defense claim.

## 5. Troubleshooting

**Ollama connection refused**

```bash
curl -s http://127.0.0.1:11434/api/tags | jq .
```

Start `ollama serve` if needed or check `systemctl status ollama`.

**Model not found**

```bash
ollama pull llama3.2:1b
ollama list
```

**Kali reports externally managed Python environment**

Use the virtual environment commands above. Avoid installing Python packages globally.

**Port 8501 already in use**

Run Streamlit on port `8502` and open `http://127.0.0.1:8502`.

**Model responses are slow**

Try the smaller `llama3.2:1b` model, close heavy applications, and verify available RAM with `free -h`.

**Want advanced RAG or agent scenarios?**

Try the maintained repositories:

- https://github.com/SasanLabs/LLMForge
- https://github.com/OWASP/AI-Vulnerabilities-Playground
- https://github.com/OWASP/OWASP-Agentic-AI-Goat

## 6. Stop / Clean Up

Stop Streamlit with `Ctrl+C`. If you started Ollama manually, stop it with `Ctrl+C` in its terminal. You can remove `.venv` and the lab directory after your experiments; no real data is stored by this demo.
