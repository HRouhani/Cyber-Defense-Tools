# Chapter 9 Local Lab — LLM Supply Chain Security (Kali / Ubuntu)

This is a public, self-contained lab for learning supply-chain failures involving LLM data, packages, model artifacts, retrieval documents, and MCP tools. **No special cloud accounts or private training environment are required.** Most labs use the Python standard library and run on Kali with very little RAM. Optional tracks use Ollama, Hugging Face Transformers/PEFT, and the official MCP Python SDK.

> **Safety and scope:** Run these demos only on your own machine or another explicitly authorized environment. All contact information and passwords in this lab are synthetic. `.invalid` email addresses cannot deliver mail. The modified installer creates a harmless local marker. The pickle demo only calls Python `print`, not the operating system. The simulated MCP leakage is written to a local file; it does not make network requests. Do not publish intentionally modified model artifacts as if they were genuine models.

## 2. Install minimal prerequisites on Kali

```bash
sudo apt update
sudo apt install -y python3 python3-venv python3-pip git curl jq
```

Check:

```bash
python3 --version
```

A Python 3.10+ runtime is recommended. All standard-library exercises can be run without a virtual environment.

From your repository's root, open the lab:

```bash
cd labs/supply-chain-lab
python3 scripts/supply_chain_lab.py init
```

If you have run earlier experiments and need clean synthetic data:

```bash
python3 scripts/supply_chain_lab.py reset
```

**Warning:** `reset` deletes the *lab's generated* `workspace/` directory. Do not save personal files there.

## 3. Lab A — Split-view / stale-reference supply-chain risk

**Goal:** Demonstrate how a source may change after a user or system has approved or recommended it. This is a **time-of-check/time-of-use** risk; it is not the same as poisoning model training data.

```bash
python3 scripts/supply_chain_lab.py reset
python3 scripts/supply_chain_lab.py split-view approve
python3 scripts/supply_chain_lab.py split-view verify
python3 scripts/supply_chain_lab.py split-view tamper
python3 scripts/supply_chain_lab.py split-view verify
```

The second verification should print `TAMPER DETECTED` because the installer hash changed.

Optionally demonstrate the **harmless** post-install side effect:

```bash
python3 scripts/supply_chain_lab.py split-view run-demo
cat workspace/package/installation_marker.txt
```

Expected marker: `SIMULATED_INSTALL_SIDE_EFFECT`.

**What this proves:** An installer can change after the originally approved snapshot. **What it does not prove:** That a model has been re-trained or that arbitrary code from the internet is safe to execute. In a real deployment, pin exact commits and verify artifact digests before running any installer.

## 4. Lab B — Front-running data poisoning (deterministic simulation)

**Goal:** Show the effect of altering a contact list *before* an update job ingests it.

```bash
python3 scripts/supply_chain_lab.py reset
python3 scripts/supply_chain_lab.py front-run query
python3 scripts/supply_chain_lab.py front-run poison
python3 scripts/supply_chain_lab.py front-run query
python3 scripts/supply_chain_lab.py front-run train
python3 scripts/supply_chain_lab.py front-run query
```

Expected observations:

| Check | Expected email |
|---|---|
| Before source edit | `alex.rivera@company.example` |
| After edit, before update | `alex.rivera@company.example` (old model snapshot) |
| After update | `alex.rivera@external.invalid` |

This lab **simulates** the model-update lifecycle using a deterministic lookup artifact; it does **not** update neural-network weights. The optional LoRA exercise later in this README uses genuine model training.

## 5. Lab C — RAG poisoning

**Goal:** Show how changing a live source document can affect a retrieved answer *without* any training run.

```bash
python3 scripts/supply_chain_lab.py reset
python3 scripts/supply_chain_lab.py rag query
python3 scripts/supply_chain_lab.py rag poison
python3 scripts/supply_chain_lab.py rag query
```

The local lexical retriever should return a passage containing `alex.rivera@external.invalid` after poisoning. This validates **retrieval** contamination; it does not automatically validate an LLM's final answer.

### Optional: real Ollama embeddings and generation

Install Ollama using its official platform instructions: <https://docs.ollama.com/>.

Ensure Ollama is listening locally:

```bash
curl http://127.0.0.1:11434/api/version
ollama pull llama3.2:1b
ollama pull all-minilm
```

Then run:

```bash
python3 scripts/supply_chain_lab.py reset
python3 scripts/ollama_rag.py 'Who handles password resets?'
python3 scripts/supply_chain_lab.py rag poison
python3 scripts/ollama_rag.py 'Who handles password resets?'
```

The optional script calls Ollama's **`/api/embed`** and **`/api/generate`** endpoints using the Python standard library. It prints the retrieved passage **separately** from the generated answer so you can detect hallucinations or refusals. Models may not output exactly the same wording every time. This demonstration does not need FAISS or a cloud vector database.

## 6. Lab D — Poisoned code dataset

**Goal:** Inspect a manipulated instruction/answer dataset before it reaches model training.

```bash
python3 scripts/supply_chain_lab.py reset
python3 scripts/supply_chain_lab.py poison-dataset
cat workspace/training/poisoned.jsonl
```

The script adds `print("SUPPLY_CHAIN_DEMO_MARKER")` to **two** code examples and prints a unified diff. The script does **not** execute the generated snippets. Inspect what changed and ask whether the examples still pass code review.

## 7. Lab E — Genuine LoRA adapter fine-tuning (optional)

> **Hardware guidance:** This optional track requires PyTorch, Transformers, PEFT, and downloads a tiny open model. It should run on CPU but may be slow and the tiny model is deliberately weak. **This is LoRA, not QLoRA.** Full 4-bit QLoRA of multi-billion parameter models is a separate, accelerator-intensive exercise; see the Hugging Face documentation linked in Chapter 9. On a 8–10 GB RAM Kali VM, do not attempt the multi-billion parameter training procedure from a GPU-powered example.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install torch transformers peft safetensors
python scripts/optional_lora_tiny.py
```

The script trains a tiny LoRA adapter using **only synthetic poisoned code examples**, then prints a generated sample and saves adapter files under `workspace/models/tiny_lora_adapter/`.

**Important:** A falling training loss proves that optimization occurred; it **does not** prove a reliable backdoor. The generated sample may be incoherent or may omit the marker. Evaluate multiple prompts and compare a clean baseline model against the adapted model before drawing conclusions.

Optional merge:

```bash
python scripts/merge_lora.py
```

This writes a local merged model under `workspace/models/tiny_merged/` using safe serialization. It does **not** publish artifacts.

## 8. Lab F — Pickle deserialization and safer model formats

Run the harmless side-effect demonstration:

```bash
python3 scripts/pickle_demo.py
```

The demo creates its own `.pkl` file and shows that loading it calls `print` without model inference. Never try this with an unknown downloaded pickle.

Optional static scanners:

```bash
python3 -m venv .venv   # only needed if you have not made one yet
source .venv/bin/activate
python -m pip install picklescan
picklescan --path workspace/model_artifacts/toy-model.pkl
```

**Note:** The benign `print` callable may not be classified as dangerous by scanning tools. That is expected. A scanner result is evidence about known signatures, not proof that an artifact is safe. Real model deployments should prefer `safetensors`, use signed/pinned sources, and scan files before loading.

## 9. Lab G — MCP supply-chain tampering

A minimal, **dependency-free** demonstration of a tool implementation being changed while its business function still appears normal:

```bash
python3 scripts/supply_chain_lab.py reset
python3 scripts/mcp_supply_chain_demo.py baseline
python3 scripts/mcp_supply_chain_demo.py modified
python3 scripts/mcp_supply_chain_demo.py verify
```

The demonstration writes a fake password marker to a file **inside this lab** and detects the unexpected change with an artifact hash. No network traffic occurs; no real credential is used.

### Optional: run an actual MCP server and client

With your lab virtual environment active:

```bash
python -m pip install mcp
python3 scripts/supply_chain_lab.py init
python scripts/mcp_client.py
```

The client starts a local MCP server over **stdio**, lists its tool, and calls `contact_lookup` against synthetic CSV records. The server exposes a read-only tool and does not accept arbitrary SQL, arbitrary paths, or external endpoints. See the official SDK documentation for current APIs: <https://github.com/modelcontextprotocol/python-sdk>.

## 10. Lab H — Tokenizer integrity

```bash
python3 scripts/supply_chain_lab.py reset
python3 scripts/supply_chain_lab.py tokenizer audit
python3 scripts/supply_chain_lab.py tokenizer tamper
python3 scripts/supply_chain_lab.py tokenizer audit
```

Inspect both hash values and the new vocabulary key. The JSON files are **illustrative mappings, not usable model tokenizers**. A tokenizer mismatch may cause errors rather than a working backdoor; compare against the matching upstream model revision.

## 11. Troubleshooting and cleanup

- **`ollama: command not found`:** Ollama is optional. Complete the standard-library labs or install Ollama separately.
- **`Connection refused` on port 11434:** Start your local Ollama service, check `curl .../api/version`, and confirm `OLLAMA_HOST` if using a nondefault bind.
- **Out of memory during LoRA:** The optional example is lightweight; close other applications or skip training. For real QLoRA, use a machine with a compatible accelerator.
- **`ModuleNotFoundError: mcp`:** The real MCP track requires `python -m pip install mcp` inside the active virtual environment.
- **`mcp_client.py` API changes:** The official MCP SDK evolves; consult its current quickstart. The standard-library integrity demo remains independent of it.
- **Unexpected old values:** Run `python3 scripts/supply_chain_lab.py reset` to restore the baseline.

To stop any optional Ollama service, follow your platform's service manager instructions. To delete generated lab files, remove only `workspace/` after confirming you have no personal files there. Do not commit model checkpoints or demonstration secrets to a public repository.

## 12. Evidence to capture

For reproducible reports, capture a **before/after pair** for each experiment: source filename and hash, the exact query used, the retrieved passage or generated output, which trust boundary failed, and one remediating control. Avoid treating every model-generated statement as a verified fact.
